## 3. Matchroom projection fix (A1) — `convex/matchrooms.ts`

`getById` no longer spreads the raw document to all callers. New `projectMatchroomForViewer(ctx, room)`:
- **Authorized actors** (host / either captain / joined participant / owning zone admin / super admin, via existing `resolveCheckInAccess`) → **full document** (`accessLevel: "full"`) — byte-identical to before, so the rich lobby UI for members is unchanged.
- **Outsiders** → `buildPublicMatchroomView(room)` (`accessLevel: "public"`): allow-listed fields only — title, description, game, status, format/seriesType/maps, skillLevel, team mode/name, seat counts, sanitized players (username/role/skillTier, **no uid**), location/areas, schedule, pricing, host display name, join/lock flags. **Omitted:** GPS `coordinates`, all `playerUids`/host/captain/zoneOwner UIDs, raw slots, `paymentStatus/Amount/...`, `sourcePaymentOrderRefNum`, `merchantSettlement*`, `venuePayout*`, `resultVerification`, `cancelReason/Note`, `clientCreateRequestId`, `matchCode`.

## 4. getByMatchCode fix (A2) — `convex/matchrooms.ts`

`getByMatchCode` now routes through the same `projectMatchroomForViewer`. A guessed/known code returns the public-safe projection (or null) to non-members and **never echoes `matchCode`** back. Authorized zone admins/participants still receive the real code (for check-in) unless the room is terminal.

## 5. Private matchroom read behavior (A3) — `convex/matchrooms.ts`

For `isPrivate` rooms, true outsiders receive `null` (→ client shows "Matchroom not found"). To avoid breaking invite/team flows, `viewerMayViewPrivateMatchroom` grants a public-safe view to: assigned team-challenge members (`assignedTeamMembers`) and holders of a pending matchroom invite (`notifications` indexed `by_matchroomId`, `type` starts `match.`, `status: "pending"`). Full members are already authorized via `resolveCheckInAccess`.

## 6. Zone public projection fix (A4) — `convex/zones.ts`

`buildPublicZoneView(zone)` strips `ownerUid`, `ownerUsername`, `ownerFullName`, `notes`, `rejectionReason`, `migration`, `pilotPayoutRate`, `normalPayoutRate`. Applied to `getById` and `getByIdString` (defense-in-depth — they can no longer leak regardless of caller) and exposed as explicit `getPublicVenueById`/`getPublicVenueByIdString`. Player venue path (`getZoneById`→`getPlayerVenueDetails`, matchroom-create) and team-challenge rate lookup repointed to the public queries. Owner dashboard is unaffected — it reads via `getByOwner` (full data for the owner); super admins read via the separate `api.admin` namespace.

**Design choice:** a *denylist* of the sensitive set (rather than a fresh allow-list) was used so the existing `transformZone` keeps working unchanged while the sensitive fields never reach the wire. `ownerUid` is intentionally stripped (the player matchroom-create path uses the walk-in admin zone's owner, not the player-selected zone's — verified — and the server resolves `zoneOwnerUid` itself). Intentionally-public `contactPhone`/`contactEmail` and customer pricing are retained.

## 7. Matchroom route guard (B1) — `app/matchrooms/_layout.tsx`

Added `useAuth` loading spinner + `Redirect` to `APP_ROUTES.authLogin` for logged-out users (mirrors `teams/_layout.tsx`). Zone admins and super admins are intentionally allowed through (owning-zone check-in / oversight). Backend projection remains the real boundary; this just sends anonymous deep-link/QR opens through login first.

## 8. MatchCode fallback removal (B2) — `app/matchrooms/utils/matchroomLobbyState.ts`

`const matchCode = room?.matchCode || (room?.id ? room.id.slice(-6)...)` → `const matchCode = room?.matchCode || ""`. The client never synthesizes a code from the public room id; it only surfaces a code the server explicitly returned.

## 9. Terminal matchCode handling (B3) — `convex/matchrooms.ts`

`projectMatchroomForViewer` nulls `matchCode` for authorized actors when the room is `completed`/`expired`/`cancelled` (`isTerminalMatchroomStatus`). No active check-in code persists on finished rooms server-side; the client already suppresses the QR for terminal status.

## 10. QR / check-in privacy (B4)

QR encodes only the route `matchhai://matchrooms/<id>` (no token/secret). The QR card stays gated by `canViewCheckIn && isLocked` in `MatchroomSummarySection` (unchanged). With B2+B3 + the public projection (`canViewCheckIn: false`, `matchCode: null` for outsiders/terminal), outsiders never see a code, terminal rooms never expose one, and share text never contains one. No component change needed.

## 11. Private team roster (C1) — `convex/teams.ts`

`getWithMembers`: for `visibility === "private"` teams, non-members (not captain, not in `memberUids`, not super admin — via non-throwing `isTeamViewerMember`) receive `{ ...team, members: [], memberCount, rosterRestricted: true }` — member identities hidden, safe count + public header retained for a join CTA. Public teams and members are unchanged. (Team detail screen uses `api.teams.getWithMembers` directly, so this takes effect; a restricted view yields `isMember=false` → existing "private" button state.)
