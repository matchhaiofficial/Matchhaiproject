## Status meanings

- **fixed/verified** — the implementation and a local test or direct source contract support the claim; no external runtime dependency remains for this narrow claim.
- **fixed-needs-runtime** — static implementation and local tests are present, but staging/device/provider/multi-user evidence is still required.
- **open** — a concrete code or configuration gap remains.
- **blocked** — the next verification cannot be performed in the current environment because an external prerequisite is unavailable; this is not a claim that the behavior is correct in production.
- **intentionally deferred** — explicitly retained for compatibility or product scope, with a guard or documented follow-up.

## Compatibility and removed-path review

The old Firebase/backend paths are not active callers in the current tree. Historical commit `8ca3b05` removed the Firebase config/rules, `functions/*`, old Firebase services, old home/find-match/request-slot routes, seeders, and the old request path. Commit `715227e` removed direct Steam/FACEIT/PSN service implementations; `src/services/convex/externalApiService.ts` is the active Convex-mediated path. Commit `5f124ae` removed the old matchroom request-slot route, request service, and store. Current `src/services/*.ts` wrappers that remain are explicit backwards-compatible re-exports to `src/services/convex/*`, not parallel backends.

The remaining legacy behavior is deliberate and bounded:

- `convex/legacyCompatibility.ts` recognizes old booking/request rows only when canonical workflow/resource metadata is absent. `convex/bookings.ts` serializes or transitions supported legacy rows but rejects changing/reopening closed legacy offers. `__tests__/unit/legacyCompatibility.test.ts` and `__tests__/security/urgentBoundaries.regression-1.test.ts` assert this boundary.
- Canonical and legacy super-admin role spellings are accepted on read (`super_admin` and `super-admin`) for migration compatibility; abuse tests cover the role boundary.
- Legacy branch arrays, old game aliases, and legacy auth/profile identifiers have explicit fallback/migration code. These paths need migration fixtures, but no evidence was found of an active removed Firebase caller.
- `convex/teamChallenges.ts` retains a legacy free/social challenge contract and rejects linking through the old free-match path when canonical paid state is required. This is compatibility behavior, not proof that all old clients are supported.
- `convex/fullDataReset.ts` refuses the old unprotected wipe path and directs callers to protected reset; demo/dev seeds are environment/key-gated.

No current client call was found for the `legacyCompatibility` module itself; its consumers are backend booking paths. Generated API entries are not evidence that an endpoint is live. Conversely, route/source presence is not evidence of a tested caller: `docs/PAGE_COVERAGE.md` still has smoke TODOs for registration, chat, challenge, zone booking, and super-admin journeys.
